# MCP Draft 2026-07-28 V2 Support

This page is the entry point for the ABAP MCP SDK v2 documentation. It gives the high-level model and links to the detailed feature docs.

The v2 implementation targets MCP draft protocol version `2026-07-28`. It is intentionally separate from the legacy server API:

- Legacy servers use `ZIF_MCP_SERVER` / `ZCL_MCP_SERVER_BASE`.
- Modern v2 servers use `ZIF_MCP_SERVER_V2` / `ZCL_MCP_SERVER_BASE_V2`.
- A stateless compatibility adapter lets old SDK clients call v2-only servers where the old protocol shape can reasonably represent the result.

Status: support for the targeted draft is complete for the currently feasible ABAP implementation. Re-check the official draft schema and transport pages before a release because the draft can still move.

## Implemented Scope

The current v2 path includes:

- stateless per-request metadata through `params._meta`
- modern HTTP routing without protocol sessions
- `server/discover`
- tools, prompts, resources, resource templates, completions
- result envelopes with `resultType`
- MRTR `input_required` for `tools/call`, `prompts/get`, and `resources/read`
- elicitation input requests inside MRTR
- central protected `requestState` helpers
- Tasks extension support for task creation, polling, input updates, cancellation, and terminal results/errors
- mirrored HTTP header validation for `Mcp-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, and `Mcp-Param-*`
- top-level `x-mcp-header` support for string, integer, and boolean tool arguments
- v2-only Origin validation and CORS preflight behavior
- stateless legacy SDK compatibility for old clients calling v2-only servers
- demo servers for normal v2 features and advanced workflow features

## Main Differences From Legacy Servers

Legacy MCP versions use `initialize` and may use protocol sessions. V2 does not.

Every modern request must carry:

- `io.modelcontextprotocol/protocolVersion`
- `io.modelcontextprotocol/clientInfo`
- `io.modelcontextprotocol/clientCapabilities`

HTTP clients must also mirror selected values into headers. The body remains the source of truth, and mismatches return `HeaderMismatch` (`-32001`).

Modern successful responses should include `resultType`. Most v2 server implementations should use the modern helper classes instead of returning raw legacy helper output.

## Compatibility Summary

Old SDK clients can initialize and use the compatibility adapter for practical legacy calls:

- `ping`
- tools
- prompts
- resources and resource templates
- completions
- task create/get/result/list/cancel translation

Modern-only flows cannot be made successful legacy results:

- MRTR `input_required`
- elicitation
- input-required task states and `tasks/update`
- `server/discover`
- `tools/get_input_schema`
- subscriptions and request-scoped streaming

See [V2 Legacy Compatibility](V2LegacyCompatibility.md) for the full matrix.

## Demo Servers

The SDK contains two v2 demo servers:

| Area | Service | Class | Purpose |
| ---- | ------- | ----- | ------- |
| `demo` | `demo_v2_basic` | `ZCL_MCP_DEMO_SERVER_V2_BASIC` | Normal tools, prompts, resources, templates, completions, cache hints, and `x-mcp-header` |
| `demo` | `demo_v2_workflow` | `ZCL_MCP_DEMO_SERVER_V2_WF` | MRTR, elicitation, protected `requestState`, persisted task input, and `tasks/update` |

The workflow endpoint uses the readable service name `demo_v2_workflow`; the class uses `WF` because ABAP class names are limited to 30 characters.

See [V2 Demo Servers](V2DemoServers.md) for short excerpts from the implemented classes.

## Explicit Non-Goals

The following are not part of the current ABAP v2 target:

- request-scoped SSE responses
- long-lived `subscriptions/listen`
- full legacy protocol sessions on v2-only servers
- server-initiated JSON-RPC requests outside MRTR
- deprecated roots/sampling/logging helper expansion unless a concrete compatibility requirement appears
- MCP Apps
- runtime OpenTelemetry integration
- automatic conversion of arbitrary legacy helper output into v2 envelopes
- external key-provider/key-rotation hooks for `requestState`
